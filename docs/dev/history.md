# 開発の経緯

> research-memory プラグインを作った会話（2026-10 〜 2026-11-01、claude.ai のチャット）の要点。新しい会話はここから続きを始める。
> 「決めた人」は特記がなければユーザー。AI の提案をユーザーが採用したものは「提案を採用」と書く。

## 1. 目的（最初の依頼）

研究室の研究サーバーで、VS Code の Remote-SSH 経由で Claude Code を使って研究を進める。そのとき次を満たす仕組みを、再利用できる形（プラグイン）で作る。

1. 研究の記憶がセッションをまたいで失われない。人（自分・指導教員）も経緯を追える。
2. 研究に合った考え方のルール（公平な比較、データリーク、事実と推測の区別、最新情報の確認）。
3. 研究で AI を使っても問題にならない使い方（論文は書かせない、出典の明記など）。

## 2. 設計の決定（主なもの）

| 決定 | 理由 | いつ |
|---|---|---|
| AI は論文・原稿を書かない。調査と研究作業だけ | 研究での AI 利用として許される範囲に限る | 初期 |
| AGENTS.md は薄く（必ず守ること・いつ何を使うか）、詳細は Skill と hooks に | 毎回読まれる文を短く保つ | 初期 |
| 記憶の分担: AGENTS.md（ルール）／MEMORY.md（今の状態、編集は承認制）／logs/YYYY-MM-DD.md（経緯、1日1ファイル、目次付き、追記のみ）／docs/（研究の背景・データ・文献） | 状態と経緯を混ぜない。推測が確定事項として固定されるのを人の目で防ぐ | 初期 |
| hooks で強制: SessionStart で MEMORY.md と当日ログの目次を渡す、Stop で記録漏れを止める（スクリプト＋AI判定）、PreCompact で会話の控え（14日で削除）、PreToolUse で MEMORY.md を承認制 | ルールを書くだけでは守られないため | 初期 |
| hooks は MEMORY.md と logs/ があるリポジトリでだけ動く。導入は `--scope local` | 研究と関係ないリポジトリや研究室の人に影響させない | 初期 |
| 文献管理は claude-scholar（MIT）の文献部分を参考に取り込む（1論文1ノート、根拠の強さ、BibTeX は DOI/arXiv からのみ、目次は自動生成）。全体の乗り換えはしない | 必要な部分だけ。Obsidian 連携は今は不要 | 初期 |
| AI だけが読む文は英語、人が読むものと記録は日本語 | トークン節約。記録は日本語で残したい | 0.2.0 |
| 「根拠上の問題には同意せず指摘する」を AGENTS.md に | 迎合を防ぐ | 0.2.1 |
| 機密情報の技術的な遮断は今は入れない（ルールのみ） | ユーザーの判断（「一旦要らない」） | 2026-10-08 |
| claude.ai / Claude Code の Projects のメモリは研究の記憶に使わない | 自分のマシンで動くスレッドはプロジェクトメモリを読まない。研究リポジトリは GitLab なのでクラウドのスレッドも使えない。承認制・記録の強制・経緯も残らない | 2026-10-27 |
| 配布は zip ではなく GitHub リポジトリ（dice-2004/research-memory）。サーバーは clone して `git pull` で更新 | 更新と逆輸入（サーバーでの変更の取り込み）を楽にする | 2026-11-01 |
| vitcore-loco で育った運用を逆輸入（0.3.0〜0.3.4）: 食い違いの申告、コミットは依頼制、CONTRIBUTING.md・how_to_run.md・experiments.md・results.md・decisions.md、結果の索引、MEMORY.md の古い判断の退避、見積もりは実行しない、最小差分、変更前に結論を示す、足したものは伝える | 実際の運用で必要になったもの | 2026-11-01 |
| 研究リポジトリのアップグレードの仕組み（research-init のアップグレードモード、template_version、版のタグ、古いとセッション開始時に通知） | 今後も同じ手順で更新できるように | 0.3.2 |
| エージェントの編集の記録（PostToolUse）と、未コミットの変更への `[agent …]` の印 | コミットを依頼制にしたので、AI の変更とユーザーの変更を取り違えやすい（vitcore-loco 2026-10-25 19:33 の懸念） | 0.3.3 |
| ブランチは一切削除しない（不採用は archive/ タグ） | README と CONTRIBUTING.md の矛盾をユーザーが「削除しない」で決着 | 0.3.5 |
| **変更を加えて実験をやり直すときは、新しいブランチと実験ID**（結果は新しい `exp-NNN_<名前>/`）。変更なしのやり直しは同じIDで、上書きになるなら先に確認 | ユーザーの決定（vitcore-loco の `results/exp-NNN_<名前>/` の形が一番よい） | 0.3.6 |
| `watch` の既定から `outputs/` を外す | 実験の実行中に変わり続け、Stop hook が毎回止めるため（`results/` を外したのと同じ理由） | 0.3.6 |

## 3. 検討して採らなかったもの

| 案 | 採らなかった理由 |
|---|---|
| claude-scholar への全面的な乗り換え | 研究記録の仕組みはこちらが合っている。文献部分だけ取り込んだ |
| すべてのファイルを英語で書く | 記録は日本語で残したい。AI だけが読む部分だけ英語にした |
| Projects のプロジェクトメモリで研究の記憶を持つ | 上の表のとおり |
| `watch` に `results/` を入れる | 実行中に変わり続ける（vitcore-loco 2026-10-25 19:42 の決定）。0.3.4 の提案から除外 |
| マージのたびに `exp-NNN` タグを機械的に付ける | 人が判断して付ける運用にした（2026-11-01） |
| マージ後・不採用でブランチを削除する | 一切削除しない（0.3.5） |
| 運用ルールを auto memory に置く | Git に残らず、ほかのサーバーや人に伝わらない。リポジトリに書く |
| `scripts/save_run_info.sh`（vitcore-loco）の取り込み | Docker の運用に依存している。汎用化が必要になったら検討 |
